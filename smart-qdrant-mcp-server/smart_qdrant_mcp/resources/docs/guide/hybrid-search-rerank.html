01 / The intuition

Three ideas. Better search.

Imagine asking a librarian for help. They look for related ideas, check the important terms, then read the promising passages more closely.

01 / DENSE◎

Look for meaning.

Turn text into a list of numbers called a vector. Texts with similar meanings can land near each other, even when they use different words.

“change my flight” can find “modify a booking”.
02 / SPARSE#

Keep the words that matter.

Use a small set of weighted vocabulary signals. Names, specialist terms, and other specific words provide clues that meaning alone can miss.

“change fee” helps surface fee-related passages.
03 / RERANK↗

Take a closer look.

A second model reads the question alongside each shortlisted passage. It can move a direct answer above a result that is only broadly related.

A policy that answers the question can rise above a fee glossary.

Prefer to read? The whole journey in six sentences
  1. Ask. The middleware receives your question and coordinates the request.
  2. Encode. Smart Embedder creates dense and learned sparse query vectors.
  3. Retrieve. Qdrant runs two searches over vectors already stored for your passages.
  4. Fuse. Qdrant combines rank contributions and returns a deduplicated candidate pool.
  5. Rerank. Smart Embedder scores question–passage pairs from a limited window; the middleware reorders it.
  6. Return. The middleware returns the requested page of matches, with text and scores.

This is a teaching simulation, not a live search or benchmark. Passage text, retrieval rankings and reranker scores are hand-authored. RRF scores and the shortlist are calculated in your browser. The examples use equal weights, k = 2, and a stable passage-ID tie-break. Reranker scores are not probabilities that the passage is correct.

Under the hood: how the RRF score is calculated

Each list contributes credit based on where it places a passage. Add those contributions; a missing passage contributes zero. In Qdrant’s equal-weight RRF, ranks start at zero.

RRF = 1 / (k + dense rank) + 1 / (k + sparse rank)

For the policy at visible position #3 in both lists, the internal ranks are 2 and 2. With k = 2: 1 / (2 + 2) + 1 / (2 + 2) = 0.500. A passage found by only one branch has only one term. The lab keeps the best N fused candidates, reranks only the selected head, and appends the unchanged tail before showing three results.

RRF is the default in this stack. DBSF is another supported fusion method; it normalizes score distributions before combining them. The lab demonstrates RRF only. Read Qdrant’s fusion reference ↗

04 / In Smart Semantic Searcher

Who does what?

The animation follows this repository’s architecture. Three separate services cooperate through explicit HTTP requests.

01 / THE COORDINATOR

Middleware

Your application’s entry point. Checks the request, calls the models and Qdrant, reorders the results, then returns them.

middleware-qdrant-manager
02 / THE MODELS

Smart Embedder

Turns text into vectors and scores query–passage pairs. Models run locally on CPU or GPU; this service does not store your collection.

server-embedder-reranker
03 / THE VECTOR DATABASE

Qdrant

Stores vectors and passage payloads. Runs the two retrieval branches and fuses their rankings before returning candidates.

Your Qdrant instance, external or bundled

Application → Middleware → Smart Embedder (encode) → Middleware → Qdrant (retrieve + fuse) → Middleware → Smart Embedder (rerank) → Middleware → Application

Before the search startsDocuments must already be split into passages, embedded and stored. Querying does not re-embed the whole collection. The optional MCP server gives agent clients another way to call the middleware.

05 / What to remember

Better results are a trade-off.

There is no setting that wins for every collection. Evaluate with real questions and passages you know should be found.

Candidate pool

Give good evidence a chance.

Retrieving more candidates may catch useful passages a smaller pool misses. It also adds work. A reranker cannot recover anything that never reached its shortlist.

Rerank window

Spend attention selectively.

A larger window gives the model more passages to compare with the question. It usually costs more time and compute. A window of one cannot change the order.

Source quality

Relevance is not truth.

A well-ranked passage can still be outdated, incomplete, or wrong. Preserve source information, check the evidence, and measure quality on your own use case.

Retrieve for coverage.
Rerank for a better first result.
Keep the source in view.

The animation uses 50 candidates per branch, a rerank window of 20, and a return limit of 5. The shipped return-limit default is 10. These are configurable limits, not guaranteed result counts or performance claims. See the middleware query reference for the actual request contract.

A little less jargon.

What is a chunk or passage?

A piece of a document that can be retrieved on its own. It should contain enough context to be useful. Splitting a policy in the wrong place can separate an answer from its conditions.

What is an embedding?

A numerical representation of text produced by a model. Dense embeddings use a fixed-length list of numbers; sparse embeddings retain weighted entries from a much larger vocabulary space.

What is a candidate?

A passage retrieved as a possible match. It may be discarded when lists are fused, fall outside the rerank window, or rank below the final results you requested.

What is a cross-encoder?

A model that scores the query and passage together. Unlike comparing separately stored vectors, it can examine how the two texts interact. This closer reading is why it is used on a shortlist.

Are fusion and reranking the same thing?

No. Fusion combines the evidence from retrieval rankings. Reranking uses a model to score query–passage pairs. In this stack, Qdrant performs fusion and Smart Embedder performs the cross-encoder reranking.

Is this retrieval-augmented generation (RAG)?

This is the retrieval part that a RAG application can use. A separate language-model step can generate an answer from the returned passages. This search pipeline itself returns ranked evidence, not a generated answer.
