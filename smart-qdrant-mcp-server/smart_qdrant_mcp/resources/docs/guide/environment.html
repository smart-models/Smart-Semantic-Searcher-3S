01 / The file itself

A small edit.
A clear intention.

Keep the full template as your starting point. You only need to change the settings that apply to your installation.

01 / Make your copy

Keep the template intact.

.env.example is the shared reference. .env is your private working copy. Keep both at the root, next to stack.ps1 and stack.sh.

If you already have .env, edit that file. Do not overwrite your existing connection details and keys with a fresh template.

02 / Edit plain text

One name. One value.

Use a plain-text editor. Keep one NAME=value assignment per line, with no spaces around =. Use lowercase true and false for switches.

A leading # disables an assignment. Uncomment an optional setting only when you intend to override its normal behaviour. An empty value is not always the same as an omitted setting.

03 / Save deliberately

A file, not a document.

Save as UTF-8 with the exact name .env, not .env.txt. Enable hidden files and file extensions if you cannot see it.

Keep comments on separate lines while learning. Avoid duplicate assignments. If a value contains special characters, follow the template’s quoting format rather than guessing.

Create your copy only if it does not already exist

Windows · PowerShell 7
if (-not (Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
Linux / macOS · Bash
if [ ! -e .env ]; then cp .env.example .env; fi

You do not need to activate a Python environment or install the model libraries on your computer for Docker startup. The launchers need Python for planning; the service libraries are built into their containers.

02 / Start with these choices

Make the first run
easy to understand.

For a first local console experience, these six choices give you an explicit CPU + basic setup.

A first console setup · edit these lines in .env

CPU. Basic models.
The search console.

STACK_PROFILE=cpu
SMART_EMBEDDER_PROFILE=basic
EMBEDDER_ONLY=false
MCP_SERVER_ENABLED=false
EXPOSE_FRONTEND=true
EXPOSE_SMART_EMBEDDER_PORT=false

This is a small set of changes to the full template, not a replacement .env file. Configure Qdrant and access below before using real data.

  1. Where the models run: cpu needs no NVIDIA GPU. Use gpu only when NVIDIA support is available to Docker.
  2. Which models: basic uses BGE; advanced uses Qwen + MILCO. Advanced works on CPU too, but is a larger starting point.
  3. Which interface: keep the full application and console. Leave MCP out until you need an AI-agent connection.
  4. How models are reached: the middleware reaches Smart Embedder privately. Publishing a separate model-service port is unnecessary for console use.

The unedited template chooses GPU + advanced, includes MCP, shows the console and publishes the embedder port. The values on the left are a deliberate alternative.

Changing models later?

A model family defines how your collection represents text. Changing SMART_EMBEDDER_PROFILE does not convert old collections. Keep the original family or plan a migration when the console reports incompatibility. Read the collection guidance ↗.

03 / Your database connection

Tell the app where
your documents will live.

Qdrant holds the collections. The application needs a reachable address and, when required, that database’s own key.

Qdrant on this Docker host

Keep the host address.

If Qdrant is already running on this computer and reachable from Docker, the supplied value is:

QDRANT_URL=http://host.docker.internal:6333

The hostname means “the Docker host” from the middleware container. Qdrant must actually be reachable there; an address that opens in your browser alone does not prove container access.

Qdrant on another machine

Use its service URL.

Set QDRANT_URL to the exact HTTP(S) endpoint supplied for that instance. Include the port if its operator specifies one.

If it requires a key, put that instance’s key in QDRANT_API_KEY. Keep the key out of the URL. Network rules must allow the middleware to reach the endpoint.

No Qdrant instance yet

Let the stack start one.

Set QDRANT_BUNDLED=true and a QDRANT_API_KEY (section 05). The launcher then runs a Qdrant container next to the middleware, reachable from this computer only at QDRANT_PORT, with its data in a Docker volume.

Prefer a separate instance? The official Qdrant quickstart ↗ covers one. Its database access and storage need their own configuration.

Understand the service setup ↗
Three addresses, three jobs

6336 is the supplied console/API port; 6333 is Qdrant’s usual HTTP port; 8010 is the optional direct Smart Embedder host port. In a container, localhost refers to that container. Keep the standard internal service URLs; Compose manages them for you.

If the model service is healthy but the console still reports a database connection error, check Qdrant’s running state, address, key and container reachability. Repeatedly changing model settings will not repair that connection.

04 / Before using real data

Decide who
can get in.

An API token is a secret key. The label identifies its owner; each service has its own keys and the services have separate keys for talking to one another.

Know the starting point

The template ships with empty API token lists and all three *_ALLOW_UNAUTHENTICATED_LOCAL switches set to true. Ports default to this computer only, but other users and programs on it can still access the services. Configure authentication before storing material you care about.

You → Search app

Your console key

MIDDLEWARE_API_TOKENS lists the keys for console/API users. Register only the secret part in the console’s API key field.

Agent → MCP

Your agent’s key

MCP_API_TOKENS lists static keys for MCP clients. This is a different service, with different secrets.

App → Database

Your Qdrant key

QDRANT_API_KEY comes from the database installation. It is neither the console key nor the MCP key.

Protect a full stack in four steps.

  1. Create separate random secrets. For the full stack in static mode, prepare five distinct values with a password manager or another secure generator: one for each service’s token list, plus the two service-to-service credentials below. Keep the Qdrant key separate too.
  2. Fill the three token lists. Each entry is secret:label. A label such as alice identifies the user; it is not part of the secret. Add more users as comma-separated entries. Labels use letters, digits, dots, underscores or hyphens; never start one with @.
  3. Connect the services. MIDDLEWARE_CLIENT_TOKEN is what MCP sends to the middleware. SMART_EMBEDDER_CLIENT_TOKEN is what the middleware sends to Smart Embedder. Each is accepted by its target automatically; enter it once, without a label.
  4. Disable unauthenticated access. Set all three *_ALLOW_UNAUTHENTICATED_LOCAL switches to false. Save, verify and apply the file with the steps below. Register your middleware secret in the console.
Format illustration · not usable credentials

Different doors.
Different keys.

MIDDLEWARE_API_TOKENS=<unique-console-secret>:alice
SMART_EMBEDDER_API_TOKENS=<unique-direct-model-secret>:operator
MCP_API_TOKENS=<unique-agent-secret>:agent

MIDDLEWARE_CLIENT_TOKEN=<unique-mcp-to-app-secret>
SMART_EMBEDDER_CLIENT_TOKEN=<unique-app-to-model-secret>

MIDDLEWARE_ALLOW_UNAUTHENTICATED_LOCAL=false
SMART_EMBEDDER_ALLOW_UNAUTHENTICATED_LOCAL=false
MCP_ALLOW_UNAUTHENTICATED_LOCAL=false

Replace every bracketed value with your own different secret. Do not use the illustration literally. The three services must not accept the same credential; startup verification rejects overlaps.

Keep .env private. Share a redacted description of a problem, not the file or a screenshot containing keys.

I do not use MCP. Which credentials matter now?

With MCP_SERVER_ENABLED=false, the MCP service is absent and its inbound token list is not checked. Protect the middleware and Smart Embedder, and set SMART_EMBEDDER_CLIENT_TOKEN for their connection.

When you enable MCP later, provision its static token list and MIDDLEWARE_CLIENT_TOKEN before starting it against an authenticated middleware. A disabled service is not proof its saved configuration is ready to be enabled.

Does a private embedder replace authentication?

EXPOSE_SMART_EMBEDDER_PORT=false removes the direct host port. The middleware still reaches Smart Embedder inside the Docker network. This exposure choice is separate from authentication; configure the service credentials as well.

The console still uses the middleware port. To understand the boundary, read the private-network explanation.

05 / Put an edit into effect

Save. Check.
Apply the new settings.

Editing the file does not immediately change running containers. Use this sequence after saving a configuration change.

  1. Save and verify.

    The launchers read settings; they do not repair or rewrite your file. Resolve any named configuration error first. Verification does not connect to Qdrant or load the models.

    Run from the repository root

    Windows · PowerShell 7
    pwsh stack.ps1 verify
    Linux / macOS · Bash
    bash stack.sh verify

  2. Preview the effective setup.

    Use the dry-run option to see the saved setup that would be applied. This example omits hardware/model arguments deliberately, so your configured choices are used.

    Which value wins? Command line first, then the terminal’s environment, then .env, then built-in defaults. A command-line CPU choice can override GPU in your file.

    Run from the repository root

    Windows · PowerShell 7
    pwsh stack.ps1 up -NoBuild -DryRun
    Linux / macOS · Bash
    bash stack.sh up --no-build --dry-run

  3. Apply and check health.

    After you have built images for the chosen hardware, use no-build to reuse them. On your first run or after updating application source, use normal up so the images are built.

    restart retains the old container settings. Use up to apply .env changes, then check status and the console’s health.

    Run from the repository root

    Windows · PowerShell 7
    pwsh stack.ps1 up -NoBuild -Wait
pwsh stack.ps1 status
pwsh stack.ps1 urls
    Linux / macOS · Bash
    bash stack.sh up --no-build --wait
bash stack.sh status
bash stack.sh urls
A different file?

The launcher supports an explicit environment-file option. Use that same file consistently for verification, preview and startup. Do not assume edits in the root .env apply when the command selects another file. Precedence and configuration reference ↗.

03 / Ports and addressesStart here · 7 settings

A port is the numbered door in an address. Change a published port if another program uses it. Internal container addresses are managed by Compose.

MIDDLEWARE_PORTTemplate · 6336
The host port for the console and search API. The supplied console address ends in :6336. After changing this port, open the new address; the container still uses 6336 internally.
SMART_EMBEDDER_PORTTemplate · 8010
The direct host port for the model service, used only when its port is published. The internal container port remains 8000. Changing this does not move the console.
QDRANT_PORTTemplate · 6333
The host port of the bundled Qdrant, always on this computer only (127.0.0.1), where its dashboard answers. Used only with QDRANT_BUNDLED=true; the container port stays 6333.
MIDDLEWARE_BIND_HOSTTemplate · 127.0.0.1
Host address on which the console and search API are published. Keep 127.0.0.1 for this computer. A private IPv4 address lets other machines on a trusted network or VPN open it without a tunnel; it requires an access key, which then also protects the health, readiness, statistics and metrics endpoints. Wildcard and public addresses are refused.
EXPOSE_SMART_EMBEDDER_PORTTemplate · true
true publishes the model service on host loopback. Set false for deployment through the middleware; the middleware can still reach it privately. Direct host tests and benchmarks then need a different access route.
QDRANT_API_HOSTTemplate · 127.0.0.1
Middleware bind address for running it outside Docker. Stock Compose sets its own internal bind and publishes the middleware on MIDDLEWARE_BIND_HOST; this is not a LAN exposure switch.
SMART_EMBEDDER_URLTemplate · http://localhost:8010
Where native middleware finds the model service. In Docker, Compose replaces this with http://smart-embedder:8000. Do not change it to follow a host-port change.

MIDDLEWARE_API_TOKENSTemplate · empty
Comma-separated secret:label entries for people or clients using the console/API. The console's API key field takes the secret part only. Give each person a separate key for individual revocation.
SMART_EMBEDDER_API_TOKENSTemplate · empty
Keys for clients directly using Smart Embedder, in secret:label form. Keep these secrets different from all middleware and MCP credentials.
MCP_API_TOKENSTemplate · empty

MIDDLEWARE_CLIENT_TOKENTemplate · empty

SMART_EMBEDDER_CLIENT_TOKENTemplate · empty
The single secret the middleware sends to Smart Embedder. The embedder accepts it automatically; do not repeat it in its token list. Set it when the middleware calls an authenticated embedder.
MIDDLEWARE_ALLOW_UNAUTHENTICATED_LOCALTemplate · true
Permits unauthenticated middleware access only when both MIDDLEWARE_API_TOKENS and MIDDLEWARE_CLIENT_TOKEN are empty, and only on a loopback MIDDLEWARE_BIND_HOST. Any accepted token enables authentication even when this switch is true.
SMART_EMBEDDER_ALLOW_UNAUTHENTICATED_LOCALTemplate · true
Permits unauthenticated model-service access only when both SMART_EMBEDDER_API_TOKENS and SMART_EMBEDDER_CLIENT_TOKEN are empty. Any accepted token enables authentication even when this switch is true.
MCP_ALLOW_UNAUTHENTICATED_LOCALTemplate · true
Permits unauthenticated MCP access with an empty static token list, only on a loopback published address. Set false after provisioning keys. Ignored in OAuth mode.
EXPOSE_FRONTENDTemplate · true

EXPOSE_MIDDLEWARE_SWAGGERTemplate · true
Shows the middleware's interactive developer API documentation. The everyday console does not need it; false removes those documentation routes.
EXPOSE_SMART_EMBEDDER_SWAGGERTemplate · false
Shows the model service's developer API documentation. It does not control the search console or publish a port.

05 / Connect to QdrantStart here · 7 settings

The stack needs a Qdrant database: one you run separately, or the bundled one that QDRANT_BUNDLED (section 02) starts inside the stack. The key and address belong to that database, not to the console or model service.

QDRANT_URLTemplate · http://host.docker.internal:6333
HTTP(S) address of the existing Qdrant instance. The supplied host.docker.internal address reaches the Docker host. For a remote instance, use its actual service URL. Ignored with QDRANT_BUNDLED=true: the launcher points the middleware at the bundled instance instead.
QDRANT_API_KEYTemplate · empty
The key issued by your Qdrant installation, if it requires one. Leave empty only if that database accepts access without a key. This is separate from the application's bearer keys. With QDRANT_BUNDLED=true it is required and becomes the bundled instance's own key; it must differ from every application token.
QDRANT_MEM_LIMITTemplate · 4g
Memory ceiling of the bundled Qdrant container, in Docker size notation. Raise it as collections grow: vectors not kept on disk live in RAM. Unused for an external instance.
QDRANT_COLLECTIONTemplate · empty
Optional default collection name. Empty means each request must choose a collection explicitly; this is useful when working with several collections.
QDRANT_TIMEOUTTemplate · 30
Seconds allowed for a call to Qdrant. Increase only after checking the connection and the slow operation; an earlier middleware deadline can still end the request.
QDRANT_ON_DISK_PAYLOADTemplate · true
Default for storing new collections' text and metadata on disk. It controls database storage, not the files in your application folder.
QDRANT_SPARSE_FLOAT16Template · true
Uses smaller 16-bit sparse-vector values in newly created collections. Keep the supplied storage choice unless you have a reason to change the collection schema.

06 / Request limits and health checksUsually leave as supplied · 8 settings

These controls limit waiting, request size and traffic. Increasing a limit lets more work in; it does not make the machine faster.

MIDDLEWARE_REQUEST_TIMEOUTTemplate · 30
Middleware request deadline, in seconds. Ingest and export endpoints are exempt from this timer, but their dependency calls still have timeouts. For search, this deadline can expire before a longer downstream timeout.
REQUEST_BODY_MAX_BYTESTemplate · 26214400
Maximum incoming middleware HTTP body, in bytes. 26214400 is 25 MiB. This applies to uploads too, including the request's packaging.
MIDDLEWARE_RATE_LIMIT_REQUESTS_PER_MINUTETemplate · 300
Sustained per-client traffic allowance. The supplied value refills capacity at 300 requests per minute; it is a rate control, not a speed target.
MIDDLEWARE_RATE_LIMIT_BURST_SIZETemplate · 180
How much per-client traffic can arrive in a short burst before rate limiting. A larger burst can put more simultaneous pressure on the services.
HEALTH_PROBE_INTERVALTemplate · 15
Seconds between background checks of Qdrant and Smart Embedder. Health can take this long to catch up after a change; reducing the interval creates more probes.
EMBEDDER_PROBE_TIMEOUTTemplate · 3.0
Seconds allowed for one model-service health probe. This is not the time allowed to perform an embedding or start the stack.
RETRY_MAX_ATTEMPTSTemplate · 3
Total attempts for operations that are eligible for retry, including the first attempt. A value of 3 means at most two retries; some writes must not be replayed automatically.
RETRY_BASE_DELAYTemplate · 0.1
Starting delay between eligible retries, in seconds. Later delays grow and vary slightly to keep clients from retrying at the same moment.

07 / Search and rerankingAdjust after a first search · 16 settings

A result is a passage you receive. A candidate is a passage considered along the way. Reranking is a second, closer comparison with the question. Defaults must stay within their corresponding maximums; candidate limits must cover result limits.

QUERY_DEFAULT_LIMITTemplate · 10
How many final passages to return when a search request does not choose a limit. This does not say how many passages were considered.
QUERY_MAX_LIMITTemplate · 50
Highest result count a request may ask for. Keep the default result limit at or below it.
QUERY_DEFAULT_CANDIDATE_LIMITTemplate · 50
Default candidate pool considered during retrieval. A larger pool gives reranking more possibilities but costs work; it is not the final result count.
QUERY_MAX_CANDIDATE_LIMITTemplate · 200
Largest candidate pool callers can request. Keep this at least as large as the maximum result count and the default candidate pool.
QUERY_DEFAULT_RERANKTemplate · true
Enables the second, closer relevance comparison by default. true is a useful starting point; disabling it saves the rerank work.
QUERY_DEFAULT_RERANK_TOP_KTemplate · 20
Default number of candidates sent to the reranker. It is a review window, not a promise to return that many results.
QUERY_MAX_RERANK_TOP_KTemplate · 200
Upper bound on the rerank window a request may ask for. A wider window increases model work.
QUERY_RERANK_MAX_CHARSTemplate · 1000
Maximum characters of each passage sent for reranking. The stored text remains intact. 0 disables this trimming and can sharply increase the model's workload.
QUERY_DEFAULT_FUSIONTemplate · rrf
How meaning and vocabulary results are combined: rrf or dbsf. Start with rrf; compare known questions before changing the method.
QUERY_INDEXED_ONLYTemplate · false
true restricts search to indexed vector segments. Keep false while learning so newly ingested, not-yet-indexed segments are not excluded for this reason.
QUERY_HNSW_EFOptional · unset
Optional breadth of the dense-vector search. Leave commented to use Qdrant's default. Raising it can spend more search work on finding candidates.
QUERY_QUANTIZATION_RESCORETemplate · true
When searching quantized vectors, use original vectors to check the candidates again. Keep true unless you have measured the quality/speed tradeoff.
QUERY_QUANTIZATION_OVERSAMPLINGTemplate · 2.0
Extra candidate factor for quantized search before rescoring. A larger factor considers more candidates and can add work.
QUERY_FILTER_FIELD_ALLOWLISTTemplate · empty
Comma-separated metadata fields that callers may filter on. Empty permits all fields; it does not hide or remove stored fields.
QUERY_FILTER_MAX_DEPTHTemplate · 20
Maximum nesting of filter groups. Most everyday filters need only a shallow structure.
QUERY_FILTER_MAX_CONDITIONSTemplate · 100
Maximum number of conditions in a filter. It limits request complexity, not the number of results.

08 / Import and exportAdjust for your files · 9 settings

A chunk is one prepared passage. Total HTTP bytes, file bytes and chunk counts are different limits. Try smaller imports before raising caps; memory use also depends on the number of passages.

INGEST_MAX_CHUNKSTemplate · 10000
Maximum passages in one import request. All passages are embedded before the first write, so this count is a key memory safeguard. Review the container memory limit before raising it.
INGEST_MAX_FILE_BYTESTemplate · 67108864
Maximum JSON file size read from the middleware's data directory: 67108864 is 64 MiB. This is not the HTTP upload cap, and a small file can still contain too many chunks.
INGEST_DEFAULT_BATCH_SIZETemplate · 64
Default number of prepared points sent to Qdrant together. It changes upload batching, not the total import-size limit.
INGEST_MAX_BATCH_SIZETemplate · 256
Largest upload batch a request can choose. The default batch must not exceed it.
INGEST_UPLOAD_CONCURRENCYTemplate · 4
How many upload batches can be sent to Qdrant at once. More parallel uploads can increase pressure on both the middleware and database.
EXPORT_DATA_ROOTTemplate · /app/middleware-qdrant-manager/exports
Container directory for exports written as files. Stock Compose maps it to middleware-qdrant-manager/exports on the host. Changing only this string does not move the Docker mount.
EXPORT_MAX_POINTSTemplate · 50000
Maximum stored points allowed in one export. Raising it requires checking middleware memory, not just free disk space.
EXPORT_MAX_BYTESTemplate · 67108864
Maximum complete UTF-8 JSON export size: 64 MiB as supplied. Formatting and metadata count too; this is not a cap on all Python memory used during export.
EXPORT_MAX_CONCURRENTTemplate · 1
Maximum simultaneous exports per process. Extra requests receive a temporary busy response; one at a time is the supplied setting.

07 / Common questions

When a setting
does not do what you expect.

A few checks distinguish a file problem from an application or database problem.

I saved the file, but nothing changed.

Check that you edited the environment file the launcher actually uses. Use up, not restart, to apply changes. A command-line argument or terminal environment value may override the file.

For native-only settings and the collection-layout section, read the applicability note: stock Compose may not pass that variable at all.

Startup refuses my access settings.

Check that enabled services have their required keys, every service uses different secrets, and the caller has the required client token. Lists use secret:label; client tokens use only the secret. A label must not start with @.

Read the named error locally, but remove all credentials before sharing it. For the full walkthrough, return to access keys.

An import is “too large”.

Check which limit was reported. REQUEST_BODY_MAX_BYTES limits incoming HTTP data. INGEST_MAX_CHUNKS limits passages per request. INGEST_MAX_FILE_BYTES limits a staged file, not an HTTP upload.

Split the source into smaller imports first. Raising only the file-byte limit does not solve a chunk-count or memory problem.

Should I just increase every timeout?

First identify the slow dependency or operation. The middleware can end a request before a longer model-service deadline expires. A health probe, an inference deadline and the CLI startup wait are different clocks.

Review the relevant group and the logs together. Raising a timeout gives work longer to finish; it does not make it faster.

Why are models downloading again?

Check whether you renamed HF_MODEL_CACHE_VOLUME, removed volumes, changed model family or updated pinned models. A new volume name starts an empty cache; it does not move the previous downloads.

Calibration state has its own CPU/GPU volumes. Temporary compiled runtime artifacts are rebuilt after container recreation even when the model cache is intact.

Do I need to fill in all the commented options?

No. Most are deliberate escape hatches for measured tuning. Leave them commented while getting the first search working. The autotuner and device defaults choose many of these values for you.

Start with hardware, model family, Qdrant, interfaces and access. Change one later setting at a time and compare the same small set of searches.
