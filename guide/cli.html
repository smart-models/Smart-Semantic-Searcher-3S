01 / Before you type

A folder. A few tools.
A reachable database.

Prepare these once. After that, the same launcher handles your ordinary starts and stops.

The application folder

Start in the right place.

Download or clone the repository, then open a terminal in its root folder. You should see stack.ps1, stack.sh, compose.yml and .env.example.

CLI simply means “command-line interface”: type a command and press Enter. Copy the command text without adding a prompt symbol.

The tools

Docker + Python.

Docker runs the services in containers. Start Docker Desktop or your Docker Engine first. Use Compose 2.24.4 or newer and Python 3.10 or newer on your command path.

Windows examples use PowerShell 7 (pwsh). In Windows PowerShell 5.1, use .\stack.ps1 in place of pwsh stack.ps1. Bash examples also work in Git Bash.

The database

Have Qdrant ready.

Qdrant stores your searchable passages. This stack connects to an existing instance; it does not install or start Qdrant for you.

Get its address and, if required, its API key from the person managing it. For Qdrant on this Docker host, the template address is http://host.docker.internal:6333.

Set the database connection ↗

Check the tools before the first run

Windows · PowerShell 7
pwsh stack.ps1 version
docker compose version --short
py -V
Linux / macOS · Bash
bash stack.sh version
docker compose version --short
python3 -V

Allow disk space and time for container images and model downloads. The first preparation needs network access; its duration depends on your connection and hardware. CPU runs need no NVIDIA GPU. The GPU route requires a compatible NVIDIA setup accessible to Docker. Check the exact prerequisites ↗.

02 / Follow along

Your first start,
one clear step at a time.

Use this CPU + basic route if you want an explicit starting point without GPU setup. The commands apply the same choices in both shells.

  1. Create your personal settings.

    Copy the template only if .env does not exist. Open .env in a plain-text editor, check Qdrant and save it. Keep the filename exactly .env, including the leading dot.

    Follow the configuration guide for the initial settings and access keys. The template starts with authentication disabled for local practice.

    Create .env without replacing an existing file

    Windows · PowerShell 7
    if (-not (Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
    Linux / macOS · Bash
    if [ ! -e .env ]; then cp .env.example .env; fi

    What to check
    Your settings are saved in the repository root, alongside the launchers.

  2. Check the configuration.

    verify checks the token configuration and Compose security rules. It does not start or stop containers, and it does not test the connection to Qdrant or load the models.

    If it reports an error, correct the named setting and run it again.

    Run from the repository root

    Windows · PowerShell 7
    pwsh stack.ps1 verify
    Linux / macOS · Bash
    bash stack.sh verify

    What to check
    The checks finish successfully. A successful check is preparation for startup, not proof the app is running.

  3. Preview a simple first run.

    This example chooses CPU + basic, enables the console, leaves MCP out and keeps Smart Embedder private. It works without a GPU. It overrides these choices for this start without rewriting .env.

    DryRun shows the planned steps without executing them.

    Run from the repository root

    Windows · PowerShell 7
    pwsh stack.ps1 up cpu basic -Full -Frontend -NoMcp -PrivateEmbedder -DryRun
    Linux / macOS · Bash
    bash stack.sh up cpu basic --full --frontend --no-mcp --private-embedder --dry-run

    What to check
    The plan names CPU, basic and the full application, with the console on, MCP off and the embedder port private.

  4. Build and start.

    Run the same choices with the wait option. The launcher verifies, builds images, prepares models and starts the services. Keep this terminal open while it works.

    The first start can take much longer than later starts: downloads and calibration are real work. If the health wait times out, inspect status and logs before starting again.

    Run from the repository root

    Windows · PowerShell 7
    pwsh stack.ps1 up cpu basic -Full -Frontend -NoMcp -PrivateEmbedder -Wait
    Linux / macOS · Bash
    bash stack.sh up cpu basic --full --frontend --no-mcp --private-embedder --wait

    What to check
    The command finishes successfully and the serving containers become healthy. Preparation containers can finish and exit successfully; they are not servers.

  5. Find the app. Check its health.

    status shows the container state. urls shows configured addresses and whether each needs a token; it is not a live health check.

    Open the console address it prints. The default is http://127.0.0.1:6336 ↗. Register your middleware key if required, then check for HEALTHY. You can now import the guide’s small sample.

    Run from the repository root

    Windows · PowerShell 7
    pwsh stack.ps1 status cpu
pwsh stack.ps1 urls
    Linux / macOS · Bash
    bash stack.sh status cpu
bash stack.sh urls

    What to check
    The console can reach Qdrant and Smart Embedder. If urls reflects different .env defaults, use the console URL and the actual status/logs for the start you just made.

Before the next start

A bare up returns to your configured choices. The shipped template selects GPU + advanced and enables MCP. If CPU + basic is your everyday setup, save those choices in .env, or keep using the explicit command above.

04 / After the first start

The commands
you will use again.

Reading logs, applying a setting and stopping the stack are different actions. Choose the one that matches your intention.

See what the app is doing.

Show the last 80 log lines. This command returns after printing them. Leave out the tail option to keep watching; press Ctrl+C to stop watching. The services keep running.

Run from the repository root

Windows · PowerShell 7
pwsh stack.ps1 logs cpu -Tail 80
Linux / macOS · Bash
bash stack.sh logs cpu --tail 80
Finish for the day.

down stops and removes this stack’s containers. It keeps the named model and calibration volumes. Your external Qdrant instance is outside this command’s scope.

Run from the repository root

Windows · PowerShell 7
pwsh stack.ps1 down
Linux / macOS · Bash
bash stack.sh down

Do not add the volumes option for an ordinary stop: it deletes the named model cache and preparation state. A reset is not a backup.

Apply an edited .env file.

Save the file, verify it, then use up with the no-build option to reuse images you already built. This example uses the profiles now saved in .env.

Run from the repository root

Windows · PowerShell 7
pwsh stack.ps1 verify
pwsh stack.ps1 up -NoBuild -Wait
Linux / macOS · Bash
bash stack.sh verify
bash stack.sh up --no-build --wait

restart does not reload .env. It restarts the existing containers with their existing settings. If images do not exist for the selected hardware, use the normal up to build them.

Use an updated checkout.

After you obtain the new source, use the normal up so Docker rebuilds the images. This also includes updated console files baked into the middleware image.

Run from the repository root

Windows · PowerShell 7
pwsh stack.ps1 up -Wait
Linux / macOS · Bash
bash stack.sh up --wait

This uses your saved hardware and model choices. A failed image build leaves the running profile untouched. Preparation or startup can still fail later, so check health before using the app.

05 / When you need more

GPU, automatic choice
and calibration.

The first-run route is only one setup. These options explain when a different one makes sense.

Use a known NVIDIA GPU setup.

Select hardware and models separately. This chooses GPU + advanced, with the same console and private-embedder setup as the first run. Use basic instead if that is your intended model family.

Run from the repository root

Windows · PowerShell 7
pwsh stack.ps1 up gpu advanced -Full -Frontend -NoMcp -PrivateEmbedder -Wait
Linux / macOS · Bash
bash stack.sh up gpu advanced --full --frontend --no-mcp --private-embedder --wait

Changing model family does not migrate old collections. Existing collections may be incompatible; keep the original profile or plan a migration before importing more text.

Let the launcher choose the hardware and models.

auto checks local NVIDIA devices. Without a selector, it picks the one with the most total memory. At 7680 MiB (7.5 GiB) or more it selects advanced; below that it selects basic. With no detected NVIDIA device it can choose CPU + basic.

Run from the repository root

Windows · PowerShell 7
pwsh stack.ps1 up auto -Full -Frontend -NoMcp -PrivateEmbedder -DryRun
Linux / macOS · Bash
bash stack.sh up auto --full --frontend --no-mcp --private-embedder --dry-run

Read the chosen hardware and model before replacing the dry-run option with the wait option. Detection failures can stop the command; a failed GPU start is not retried on CPU. The threshold uses total memory and does not promise that your workload fits.

auto is a command-line choice only. Do not put STACK_PROFILE=auto in .env. It requires a local Docker endpoint. Detection and explicit GPU selection ↗.

Understand the preparation pause.

The autotuner tries execution settings on your hardware. The normal quick mode saves a compatible decision for later starts. full performs a longer audit; off skips this calibration and uses fallback behaviour.

Leave the normal mode in place for your first start. Model downloads are separate from tuning time. For a deliberate recalibration, use the documented autotune controls; forcing it on every launch makes startup slower.

Run only the model service.

This specialist setup removes the middleware and MCP server. It has no search console and does not provide the full document-search application. If you need it, follow the embedder-only recipe and decide whether your client needs a published model-service port.

06 / When something does not work

Start with the message
in front of you.

Check the failed step before repeating the whole start. Status and logs often tell you what needs attention.

“pwsh”, Python or Docker is not found.

Check that the required tool is installed and available in a newly opened terminal. PowerShell 7 uses pwsh; Windows PowerShell 5.1 can invoke .\stack.ps1 directly. If a script is blocked by local policy, follow your machine’s approved policy rather than disabling it broadly.

Use the prerequisite checklist to identify the missing tool.

The launcher cannot find .env.

Return to the repository root. Show hidden files and file extensions in your file browser: .env.txt is not .env. Create the file from the template if it does not already exist, then save your edits.

Startup takes a long time or the wait expires.

The first preparation downloads and calibrates models. Check status and the recent logs for the step that is still running or failed. A wait timeout does not by itself stop the containers.

The launcher’s default health wait is 600 seconds. You can choose a longer wait when logs show legitimate ongoing work; the wait-timeout option controls that wait, not model or API request deadlines.

The console opens but reports UNHEALTHY.

Open Monitoring and identify which dependency is unavailable. Check Qdrant’s address and key in .env, and Smart Embedder’s startup logs. Inside a container, localhost refers to that container, not your computer.

Fix the cause, apply changed settings with up, then choose Re-test in the console. Review the connection settings ↗.

The port is already in use, or the console is missing.

Use an unused MIDDLEWARE_PORT, apply it with up and open the new address. For a missing console, check that the middleware is included and EXPOSE_FRONTEND=true. urls helps find configured endpoints.

Only one stack can run on this machine. A different project name does not permit a second simultaneous instance.

The next start uses different models or services.

Command-line choices do not rewrite .env. A bare up uses configuration again; the supplied template chooses GPU + advanced. Save your intended choices, or repeat the explicit command. A value set in the terminal environment can also override the file.
